## 1. 需求背景与设计目标

### 1.1 需求描述
Orcsy 编排系统部署后，支持用户在智能手机（iOS / Android）等移动终端上远程连接系统，通过填写「系统 URL + 访问鉴权密码」完成接入，并在手机上实时查看、编辑或新建任意项目的任务，与桌面端后台运行的 Agent 实现无缝协同。

### 1.2 核心业务场景
1. **外出巡检与紧急干预**：开发者离开电脑后，在手机浏览器中实时查看 Agent 执行进度、审查结果及任务日志；当任务受阻（blocked）或审查未通过时，在手机上直接修改任务描述或补充指示，重新入队执行。
2. **灵感随手录入**：随时通过手机打开 Orcsy 看板，选择任意项目录入新任务，填好需求要点后保存排队，由工作站/服务器后台静默执行。
3. **局域网/跨网远程部署**：工作站位于家庭或公司局域网，手机在同一 Wi-Fi 或通过 VPN/内网穿透（FRP / Tailscale / Cloudflare Tunnel）访问。
4. **云端 VPS / Docker 长期宿主**：Orcsy 部署在公网云服务器上，多端随时随地通过 HTTPS 域名访问。

### 1.3 设计指标与约束
| 指标分类 | 目标要求 | 说明 |
| :--- | :--- | :--- |
| **网络可达性** | 支持纯局域网直连、反向代理（Nginx/Caddy）及穿透网络 | 自动感知监听地址与真实客户端来源 |
| **认证与安全** | PBKDF2 加盐密文比对，Cookie + Bearer Token 双轨认证 | 解决 iOS Safari 严格隐私策略导致的跨网/反代 Cookie 丢失问题 |
| **防爆破安全** | IP 智能滑窗限制 + 真实反代 IP 穿透支持 | 修复生产反代部署下误将 `127.0.0.1` 封禁导致的 DoS 漏洞 |
| **交互自适应** | 适配 360px ~ 430px 主流手机屏幕，触控友好 | 移动端专属布局、底部导航、避免软键盘遮挡保存键 |
| **数据一致性** | 乐观并发控制模型（Optimistic Locking） | 避免手机编辑保存时强行冲掉 Agent 刚回写的任务状态与审查结果 |
| **弱网与低耗** | 页面可见性感知（Page Visibility）+ 息屏暂停与恢复刷新 | 手机息屏时不浪费流量电量，唤醒后立即静默校验并重连 |

### 2.1 关键缺陷剖析：反向代理与登录限速导致的 DoS 漏洞
在 `orcsy/web.py` 中：
```python
result = self.state.login(str(body.get("password") or ""),
                          client_ip=self.client_address[0])
```
注释说明为“直连部署，不采信 X-Forwarded-For 以免伪造”。但在手机远程连接的典型场景中，几乎所有生产级方案都会通过 **Nginx / Caddy 反向代理接入 HTTPS** 或使用 **FRP 内网穿透**。此时 Python 后端收到的 `client_address[0]` **恒等于 `127.0.0.1`**。
* **致命隐患**：如果外部恶意探测密码，或手机因锁屏切网连续自动重试失败 5 次，系统会将 `127.0.0.1` 锁定 15 分钟。**这会导致宿主机本机也瞬间无法打开看板，产生单点拒绝服务（DoS）**。本方案必须引入受信任代理（`trusted_proxies`）名单机制。

## 3. 总体架构设计

### 3.1 部署拓扑与网络数据流
针对不同物理环境，系统支持直连与反向代理两种主流部署模式：

```
【场景 A：局域网直连 (Wi-Fi)】
  手机浏览器 ──HTTP:5116──► [工作站 / NAS (0.0.0.0:5116)] ──► Orcsy 内核 (PBKDF2 强鉴权)

【场景 B：广域网 HTTPS 反向代理 / 穿透 (推荐生产模式)】
  手机端 (Safari/Chrome/PWA)
       │
       ▼ (HTTPS: 443 + TLS 证书加密)
  [公网入口: Nginx / Cloudflare Tunnel / FRP]
       │ (HTTP 反代 + 注入 X-Forwarded-For / X-Real-IP)
       ▼
  [Orcsy 宿主机 (127.0.0.1:5116)]
       ├─ 受信任代理校验器 (校验 upstream IP 是否属于 trusted_proxies)
       ├─ 双轨认证鉴权守卫 (Cookie + Authorization Bearer Token)
       ├─ 任务乐观锁控制器 (ETag / Version Hash 核对)
       └─ 轻量增量同步引擎 (状态版本比对 + 息屏唤醒补偿)
```

## 4. 网络部署与多端发现设计

### 4.1 `web.host` 绑定扩展与启动二维码
为方便手机在同一局域网内直接扫描连接，系统在启动时自动探测本机所有非回环局域网 IPv4 地址（如 `192.168.1.105`），并在终端与桌面看板提供连接向导：

1. **配置项增强 (`config.yaml`)**：
```yaml
web:
  host: 0.0.0.0              # 允许绑定所有网卡，对外网/局域网提供服务
  port: 5116
  auth_password: "pbkdf2:..." # 必须设密码（维持原 M1 守卫逻辑）
  trusted_proxies:            # 信任的反向代理 IP 列表（CIDR 或单 IP）
    - 127.0.0.1
    - "::1"
    - 172.17.0.0/16           # Docker 默认网桥网段
  public_url: ""              # 可选：外网暴露域名（如 https://orcsy.example.com），用于生成二维码
```

2. **多网卡探测与终端二维码输出**：
   在 `web.py` 启动阶段，若 `host in ("0.0.0.0", "::")`：
   * 枚举物理网卡获取局域网 IPv4 地址；
   * 在控制台输出可访问的局域网 IP 与连接说明；
   * 桌面看板右上角新增「手机连接」入口，点击弹出手机扫码连接对话框。

### 4.2 反向代理与受信任代理头解析（修复 DoS 漏洞）
在 `web.py` 中重构客户端 IP 提取逻辑，彻底阻断反向代理下封禁本地回环的问题：

```python
import ipaddress

def _is_ip_trusted(ip_str: str, trusted_list: list[str]) -> bool:
    try:
        addr = ipaddress.ip_address(ip_str)
        for net in trusted_list:
            if "/" in net:
                if addr in ipaddress.ip_network(net, strict=False):
                    return True
            elif addr == ipaddress.ip_address(net):
                return True
    except ValueError:
        pass
    return False

def get_client_ip(handler: BaseHTTPRequestHandler, trusted_proxies: list[str]) -> str:
    """安全解析真实客户端 IP。
    只有当直连对端 IP 属于 trusted_proxies 时，才允许解析 X-Forwarded-For，
    且取代理链路中最右侧不受信任的 IP（防伪造），否则一律使用对端直连 IP。
    """
    peer_ip = handler.client_address[0]
    if not _is_ip_trusted(peer_ip, trusted_proxies):
        return peer_ip

    xff = handler.headers.get("X-Forwarded-For")
    if not xff:
        return handler.headers.get("X-Real-IP") or peer_ip

    ips = [item.strip() for item in xff.split(",") if item.strip()]
    for ip in reversed(ips):
        if not _is_ip_trusted(ip, trusted_proxies):
            return ip
    return ips[0] if ips else peer_ip
```

## 5. 双轨鉴权与远程连接模型设计

### 5.1 Cookie + Bearer Token 双轨认证机制
手机端移动浏览器（尤其是 iOS Safari）存在“第三方 Cookie 隔离”、“跨域反代 SameSite 限制”、“WebClip/PWA 独立存储隔离”等行为，纯依赖 Cookie 极易在切网或息屏后频繁登出。

为此设计**双轨认证模型**：
1. **统一令牌分发**：
   * 密码验证成功后，服务端下发 `token`：
     ```json
     {
       "ok": true,
       "token": "tok_sec_9f82c4...",
       "expires_in": 604800,
       "server_time": 1731484800
     }
     ```
   * 响应头同时下发安全 Cookie（`Set-Cookie: orcsy_session=...; Path=/; HttpOnly; SameSite=Lax`）。若在 HTTPS 下自动追加 `Secure` 标记。
2. **请求端双模鉴权**：
   * 前端每次发请求时：
     * 自动在 Header 附加 `Authorization: Bearer <token>`（从 `localStorage` 中获取）；
     * 浏览器自带的 Cookie 依然正常发送。
3. **服务端校验优先级**：
   * 服务端拦截器先检查 `Authorization: Bearer <token>`；
   * 若无该 Header，再回退校验 `Cookie: orcsy_session=...`。
   * 只要任一认证通过，即视为合法请求。即使手机丢失 Cookie，只要 LocalStorage 中的 Token 未过期，依然保持登录状态。

### 5.2 移动端连接管理器（System URL + 密码认证流程）
为了支持手机端无缝对接任意 Orcsy 实例，前端设计独立的 `ConnectionProfile` 机制：

```
                    【手机远程连接时序图】
手机客户端 (Browser / PWA)                      Orcsy 服务端 (Web Core)
     │                                                     │
     │ 1. 用户输入系统 URL (如 https://orcsy.mycorp.com)   │
     │    及 鉴权密码                                      │
     │────────────────────────────────────────────────────►│
     │    POST /api/login                                  │
     │    { "password": "...", "client_type": "mobile" }   │
     │                                                     │
     │ 2. 校验通过，签发会话 Token                        │
     │◄────────────────────────────────────────────────────│
     │    Set-Cookie: orcsy_session=... (HttpOnly)         │
     │    Body: { "ok": true, "token": "...", ... }        │
     │                                                     │
     │ 3. 前端持久化保存:                                  │
     │    - localStorage: current_server_url, auth_token   │
     │                                                     │
     │ 4. 建立长效会话，后续接口调用带 Token              │
     │────────────────────────────────────────────────────►│
     │    GET /api/state                                   │
     │    Authorization: Bearer <auth_token>               │
     │◄────────────────────────────────────────────────────│
```

* **支持多环境切换**：本地存储中可保存多个连接配置（如「办公室工作站」、「家庭台式机」），支持在移动端一键切换连接实例。

## 6. 任务实时编辑与多端并发冲突控制（Concurrency & Locking）

在手机远程操作场景下，**最严重的工程风险是手机端编辑保存时，冲掉 PC 端 Agent 正在执行或刚完成的任务数据**。必须在协议与交互层实现坚固的防护。

### 6.1 乐观并发控制模型（ETag / Version Hash）
在现有的 YAML 任务文件架构下引入轻量无状态的 **版本签名机制**：

1. **版本签名生成**：
   服务端根据任务文件的修改时间、文件大小及状态计算版本快照哈希：
   $$\text{version\_token} = \text{MD5}(\text{mtime\_ns} + \text{file\_size} + \text{status})$$

2. **GET /api/task 返回版本快照**：
   ```json
   {
     "ok": true,
     "id": "P2-fix-login",
     "project": "my-app",
     "title": "修复登录超时",
     "status": "open",
     "description": "...",
     "version_token": "1731484920-a7d4e"
   }
   ```

3. **POST /api/task 提交前置条件检查**：
   前端在保存任务时必须将 `base_version` 回传：
   ```json
   {
     "project": "my-app",
     "id": "P2-fix-login",
     "title": "修改后的标题",
     "description": "修改后的描述...",
     "base_version": "1731484920-a7d4e"
   }
   ```
   * **校验逻辑**：
     * 若 `base_version` 与磁盘当前任务文件的最新版本一致：允许写入，生成并返回新 `version_token`；
     * 若版本不一致（说明后台 Agent 已经认领任务变为 `in_progress`，或 Agent 审查退回了修改意见）：**服务端拒绝更新并返回 HTTP 409 Conflict**：
       ```json
       {
         "ok": false,
         "conflict": true,
         "message": "任务已被后台 Agent 或其他终端修改（状态已变更为 in_progress）",
         "current_task": { "...最新任务内容..." }
       }
       ```

4. **手机端冲突解决交互（Conflict Resolution）**：
   前端捕获 409 后，弹出差异提示弹窗：
   * 【保留我的修改】：强制覆盖（将当前输入作为最新版本强制写入）；
   * 【采用最新状态】：放弃手机未保存内容，重新载入最新文件；
   * 【合并查看】：高亮差异对比。

### 6.2 本地草稿实时暂存（Local Draft Auto-save）
移动端打字容易被打断（如接到电话、应用切到后台被系统杀死）。
* 前端在手机端编辑时，输入框绑定防抖（Debounce 300ms），将当前正在编辑的内容自动存储至 `localStorage.orcsy_draft_${project}_${taskId}`；
* 异常中断重新打开时，提示用户“检测到未保存的草稿，是否恢复？”，杜绝用户输入心血丢失。

### 7.2 移动端核心交互细节优化

#### B. 底部固定导航栏（Bottom Navigation Bar）
符合人体工程学，位于单手大拇指舒适操作区：
1. **看板（Dashboard）**：聚焦当前项目的任务流与最新执行进展；
2. **项目（Projects）**：卡片式浏览所有项目状态，支持快速切换活动项目；
3. **＋ 新建任务（FAB 悬浮高亮主按钮）**：点击立即呼出全屏任务新建抽屉；
4. **控制与日志（Control / Log）**：查看调度器状态、实时日志尾部与全局设置。

#### C. 任务新建/编辑：全屏抽屉与键盘自适应（Sheet Dialog）
* 现有的 `NModal` 在手机端弹出时只有 `92vw` 且上下有大边距，输入法弹起后按钮被严重遮挡。
* **重构方案**：移动端将任务弹窗切换为 **全屏抽屉（Fullscreen Sheet）**：
  * **吸顶导航条**：左上角「取消」，居中「编辑任务」，右上角高亮「保存」按钮；无论键盘如何顶起，**保存与取消按钮永远固定在可视区域最顶端**，触手可及。
  * **键盘视口感知**：CSS 声明 `height: 100dvh` 并利用现代浏览器的 `visualViewport` API，动态避让虚拟键盘高度，滚动区域（Scrollable Content）自适应压缩，杜绝任何遮挡。
  * **Markdown 辅助工具条**：在文本框上方提供移动端快捷输入栏（一键插入 `#`、`- [ ]`、`*粗体*`、` ```代码块 ` 等），极大提升手机打字效率。

#### D. 触屏拖拽与顺序调整（Touch-Friendly Reorder）
* 原生 HTML5 DnD 不支持移动端触控。在移动端上提供双重操作保障：
  * **快捷升降序按钮**：待办卡片右侧提供轻量「▲ 上移」与「▼ 下移」按钮，点击一次直接在同优先级分组内交换位置并静默调用 `/api/task/reorder`；
  * **长按拖拽支持**：引入轻量级 Touch 拖拽库，长按卡片 300ms 震动反馈后即可平滑拖动排序。

## 9. 移动端性能与网络流量优化

手机远程访问依赖移动蜂窝数据，频繁全量拉取状态极易造成发热卡顿与流量浪费：

```
                      【移动端网络智能节流策略】
┌──────────────────┐
│  手机在前台活跃  │ ──► 标准轻量轮询 (5s 一次状态摘要)
└──────────────────┘
         │ 手机锁屏 / 切换到后台应用 (Page Visibility 隐藏)
         ▼
┌──────────────────┐
│  进入休眠节流态  │ ──► 立即挂起所有轮询定时器，断开非必要请求
└──────────────────┘
         │ 手机解锁 / 重新点开浏览器标签 (VisibilityChange -> visible)
         ▼
┌──────────────────┐
│  即时唤醒重连    │ ──► 1. 发送轻量探活检查 Token 有效性
└──────────────────┘     2. 立即触发一次全量快照拉取同步
                         3. 恢复轻量轮询
```

1. **页面可见性感知（Page Visibility API）**：
   在 `dashboard/src/store.ts` 中挂载监听：
   * 息屏或后台隐藏时：立即停止定时器，防止电量与流量消耗；
   * 重新切回前台时：立即拉取一次最新状态，静默自愈并恢复轮询。
2. **轻量状态摘要拉取**：
   桌面端 `/api/state` 包含全量日志尾部（60KB）及全部任务数组。为移动端设计轻量接口 `/api/state?summary=true`，过滤掉巨大的 `log_tail` 与非活动项目归档，将每次轮询数据包从 80KB 压缩至 3KB 以下，极速响应。

## 11. 验证矩阵与自动化测试方案

### 11.1 后端自动化单元测试用例
依托工程现有的 `pytest` / `uv run pytest` 体系，编写以下针对性测试：
* `test_trusted_proxies_resolution()`：模拟来自不同代理链的 `X-Forwarded-For` 头，验证合法与伪造 IP 的解析正确性；
* `test_bearer_token_authentication()`：验证通过 `Authorization: Bearer <token>` 访问全量 API 的有效性与过期注销逻辑；
* `test_task_concurrency_conflict_409()`：模拟两个客户端同时提交任务修改，验证首个写入成功、后一个精准触发 409 Conflict 且数据未被冲掉；
* `test_login_throttle_no_loopback_lockout()`：模拟真实 IP 触发爆破锁定时，验证 `127.0.0.1` 依然畅通，不产生拒绝服务。

### 11.2 前端与移动端真实设备验证检查单
* [ ] **连接与登录**：手机在局域网内扫码直达，输入密码登录成功；刷新页面或重新打开浏览器无需重复输入密码；
* [ ] **键盘避让**：在 iPhone (Safari) 及 Android (Chrome) 上唤起输入法，编辑任务标题与大段 Markdown 描述，确认「保存」按钮完全可见，页面无不正常抖动；
* [ ] **跨项目新建与编辑**：手机端在顶部或底部快速切换到任意项目，点击 `＋` 号新建任务，保存后电脑端看板 1 秒内同步呈现该新任务；
* [ ] **息屏与切网**：手机正在打开看板时锁屏 5 分钟，重新解锁，观察页面是否自动无感重连并呈现最新任务状态。
