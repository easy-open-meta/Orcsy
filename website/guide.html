Orcsy 用户指南

面向第一次接触 Orcsy 的普通使用者：不需要懂编程，也能完成安装、接入项目、创建任务，并看懂看板上的每一条信息。

适用版本：0.18.0　|　默认看板地址：http://127.0.0.1:5116

1. 先看这里：5 分钟跑通第一个任务

如果你已经装好 Orcsy，只想马上试一次，按下面五步走：

  1. 打开看板：双击桌面上的 Orcsy 图标（开始菜单里也叫 Orcsy），或访问 http://127.0.0.1:5116。
  2. 填模型：点顶部「项目与设置」→ 在「🤖 大模型接入」卡片里填 API Key、API 地址、模型名 → 点「测试连接」→ 成功后点「保存模型配置」。
  3. 加项目：点右上角「＋ 新建项目」→ 选一个你电脑上的项目文件夹 → 点「保存」。Orcsy 会自动在该文件夹里建 tasks/ 和 AGENT.md，不会动你原来的代码。
  4. 加任务：回到「看板」页，在项目卡片里输入一句任务标题（例如「修复登录页在 125% 缩放下错位」），选优先级，点「添加」。
  5. 让它开工：点顶部「▶ 立即扫描」。任务状态会从「待办」变成「执行中」，跑完后变成「已完成」或「受阻」。完成后项目里会多出一条 Git 提交（如果项目是 Git 仓库）。

💡 第一次使用建议先拿一个测试项目或副本练手。Orcsy 会真实修改文件、真实执行命令。如果项目是 Git 仓库，改动会先在临时工作副本里完成，成功后再合并回项目；非 Git 项目则直接在项目目录里修改。

2. Orcsy 是什么，能帮你做什么

2.1 一句话说明

Orcsy 是一个「把任务写下来，就自动帮你做」的工具。 你用一个 Markdown 文件描述要做什么，Orcsy 会定时检查任务清单，把任务交给 AI 助手，让它在你的项目里读代码、改文件、跑测试，完成后自动提交 Git、更新任务状态。

可以把它想象成：

  • 你是「产品经理」，负责写清楚要做什么、做到什么程度算完成；
  • Orcsy 是「项目经理」，负责排优先级、安排谁来做、盯着进度；
  • 大模型（AI）是「执行工程师」，负责真正动手改代码；
  • 看板是「办公室大屏」，随时能看到谁在做什么、做到哪一步。

2.2 它适合做什么

  • 有明确验收标准的开发任务：修 Bug、加小功能、补测试、改文案、重构一小块代码；
  • 需要重复执行的维护工作：依赖升级后跑测试、批量修改配置、生成文档；
  • 把 GitHub / Gitee / GitLab / Gitea 上的 Issue 自动变成开发任务；
  • 多个项目排队执行，或者多个项目并行执行；
  • 晚上或周末无人值守地推进任务。

2.3 它不适合做什么

  • 需求本身很模糊，连你自己都说不清「做成什么样算完成」；
  • 需要大量产品决策、UI 审美判断、数据库结构大改的任务；
  • 需要访问生产数据库、第三方后台、密钥管理系统，但你没有把权限交给它；
  • 需要「一键上线」「自动发布到应用商店」这类高风险操作（Orcsy 不负责部署上线，只负责改代码和提交）。

2.4 使用它需要会编程吗

不需要你会写代码，但需要你能做到下面几件事：

  • 会安装 Windows 软件、会解压文件；
  • 会申请一个大模型 API Key（各家平台的网页操作）；
  • 能用一两句话把任务说清楚，最好写上「验收标准」；
  • 知道自己的项目文件夹在哪里；
  • 出问题时愿意看一眼「运行日志」里的中文提示。

如果你完全不想碰命令行，优先使用 Windows 安装包，其余步骤都在浏览器里点鼠标完成。

3. 三个核心概念，用大白话解释

3.1 项目（Project）

一个「项目」就是你的一个代码文件夹，例如 D:\Repos\my-app。

Orcsy 只在这个文件夹里做两件事：

  1. 创建（如果还没有）tasks/ 文件夹，用来放任务；
  2. 创建（如果还没有）AGENT.md 文件，用来告诉 AI「这个项目有什么规矩」。

它不会动你项目里的其它文件结构，也不会把配置、日志、技能写进项目目录。

3.2 任务（Task）

一个任务就是一个 Markdown 文件（.md），放在项目的 tasks/ 目录里。

文件名就是任务 ID，例如 P1-修复登录页崩溃.md。文件开头有一段「元信息」（标题、优先级、状态），下面是你写的需求、现象、验收标准。

你可以：

  • 在看板上点鼠标创建任务；
  • 直接往 tasks/ 文件夹里拖一个 .md 文件；
  • 用文本编辑器打开任务文件修改。

三种方式效果一样，因为看板改的就是这些文件。

3.3 Agent（AI 助手）

每个项目有自己专属的 Agent。它不是一个常驻的机器人，而是「每次领到一个任务，就临时开工」的执行者。

它工作时会：

  1. 读项目的 AGENT.md，了解技术栈、运行命令、代码规范；
  2. 读任务文件，理解要做什么；
  3. 如果项目是 Git 仓库，在项目里创建一个临时工作副本（git worktree），所有修改都先发生在这里；非 Git 项目则直接在项目目录里修改；
  4. 读文件、改文件、跑测试、跑构建；
  5. 完成后报告结果，由 Orcsy 统一提交、合并回主分支；
  6. 把结果写回任务文件，并把完成的任务归档到 tasks/done/。

💡 为什么要用临时副本？因为 AI 也会犯错。Git 项目里所有改动先在副本里做，确认没问题再合并；如果任务受阻，副本会被丢弃，你的主工作区不会被弄脏。非 Git 项目没有这层保护，首次使用更建议先备份或在副本上练习。

4. 安装部署：选一种适合你的方式

4.1 先选方式

你的情况 推荐方式 难度 需要什么
Windows 个人电脑，想最省事 Windows 安装包 ★☆☆ 一个 API Key
想查看/修改源码，或参与开发 源码运行 ★★★ 会一点命令行，装 uv
服务器、NAS，不想装运行环境 Docker Compose ★★☆ 会 Docker 基本操作
Linux 服务器，想开机常驻 Linux systemd ★★★ root 权限，会一点 Linux

对绝大多数普通用户，选 Windows 安装包就够了。

4.2 方式一：Windows 安装包（推荐）

准备工作

  • Windows 10 / 11；
  • 一个大模型 API Key（例如 DeepSeek、智谱 GLM、Kimi、OpenAI、通义千问等）；
  • 一个你想交给 Orcsy 的项目文件夹；
  • 建议项目是 Git 仓库（不是也能用，只是不会自动提交/合并）。

安装步骤

  1. 打开项目发布页，下载 orcsy-setup-0.22.0-windows-amd64.exe。
    • Gitee：https://gitee.com/java-and-net/Orcsy/releases
    • GitHub：https://github.com/easy-open-meta/Orcsy/releases
  2. 双击安装包。如果 Windows 弹出「已保护你的电脑」，点「更多信息」→「仍要运行」。
  3. 按向导点「下一步」。安装位置可以保持默认 C:\Program Files\Orcsy，也可以改到一个你有写权限的目录（例如 D:\Tools\Orcsy）。
    • 装在 C:\Program Files 下：以后自动更新时会弹一次管理员授权（UAC），点「是」即可；
    • 装在用户可写目录：以后更新全程无弹窗，更省心。
  4. 附加任务里可以勾选「初始化示例任务」。它只会在数据目录放一份任务模板，方便你参考，不勾也不影响使用。
  5. 点「安装」，完成后程序会自动启动：
    • 右下角任务栏出现 Orcsy 托盘图标；
    • 浏览器自动打开看板 http://127.0.0.1:5116。
  6. 如果浏览器没有自动打开：右键托盘图标 →「显示主界面」，或手动访问上面的地址。

安装后你要知道的三件事

  • 数据目录：C:\Users\<你的用户名>\AppData\Roaming\Orcsy
    • config.yaml：配置文件（含 API Key，不要发给别人）；
    • skills\：技能库；
    • logs\：运行日志；
    • logs\usage.jsonl：用量记录。
  • 程序目录：只放程序本体，不放你的数据。
  • 卸载：Windows「设置 → 应用 → 已安装的应用」里找到 Orcsy 卸载；卸载时可以选择是否一并删除数据目录。

⚠️ 第一次启动会自动生成 config.yaml，你不需要手动创建。模型密钥推荐在看板里填，保存后立即生效。

4.3 方式二：源码运行（适合想看源码的人）

前提：电脑上已安装 uv（一个 Python 环境管理工具）。没有 Python 也没关系，uv 会自动准备 Python 3.11+。

# 1. 下载源码
git clone https://gitee.com/java-and-net/Orcsy.git orcsy
cd orcsy

# 2. 安装依赖
uv sync

# 3. 生成配置和模板到 run/ 目录
uv run orcsy init --dir run

# 4. 编辑 run/config.yaml：至少填 api_key、base_url、model
#    然后把 projects 指向你的项目（用绝对路径）

# 5. 检查配置和任务格式
uv run orcsy validate --config run/config.yaml

# 6. 启动看板（同时启动定时调度，并自动打开浏览器）
uv run orcsy web --config run/config.yaml

常用启动参数：

参数 作用
--port 8080 换一个看板端口
--host 0.0.0.0 允许局域网访问（必须同时设置登录密码）
--no-browser 启动时不自动打开浏览器
--no-tray 不显示系统托盘图标
--no-sched 不启动定时调度，只保留手动「立即扫描」

只想当命令行调度器、不要看板：

uv run orcsy run --config run/config.yaml          # 持续调度
uv run orcsy run --config run/config.yaml --once   # 只跑一轮就退出（适合计划任务/cron）

4.4 方式三：Docker 部署（服务器 / NAS）

前提：服务器已安装 Docker 和 Docker Compose。

# 1. 在项目根目录构建并启动
docker compose up -d --build

# 2. 第一次启动会生成 ./orcsy-data/config.yaml
#    因为容器对外监听 0.0.0.0，必须设置登录密码，否则会拒绝启动
#    编辑 ./orcsy-data/config.yaml，把 web.auth_password 改成强密码
docker compose restart

# 3. 浏览器打开
#    http://<服务器IP>:5116

目录对应关系：

宿主机 容器内 放什么
./orcsy-data /data 配置、技能库、日志、用量记录
./projects /projects 受管项目（建议每个项目一个子目录）

重要规则：

  • 看板里新建项目时，项目路径要填容器内路径，例如 /projects/my-app，对应宿主机的 ./projects/my-app；
  • 宿主机上的 ./projects/my-app 需要是 Git 仓库；
  • 如果要让 Orcsy 能推送到远程仓库，需要配置 Git 凭据：
    • HTTPS：把 token 写进远端地址；
    • SSH：按 docker-compose.yml 里的注释挂载 ~/.ssh。
  • 查看日志：docker compose logs -f；
  • 停止：docker compose down；
  • 升级：备份 ./orcsy-data，拉取新源码后重新 docker compose up -d --build。

4.5 方式四：Linux 原生部署（systemd）

前提：Linux 服务器、root 权限、已安装 git。

# 在源码根目录执行（需要 root）
sudo bash deploy/linux/install.sh

# 安装脚本会自动：
# - 安装 uv
# - 创建专用用户 orcsy
# - 把程序放到 /opt/orcsy
# - 把数据放到 /var/lib/orcsy
# - 把受管项目目录设为 /srv/orcsy-projects
# - 生成随机登录密码并打印在安装输出里

安装完成后：

  1. 浏览器打开 http://<服务器IP>:5116；
  2. 用安装输出里的密码登录；
  3. 在「项目与设置」里填模型密钥，新建项目时路径填 /srv/orcsy-projects/<项目名>。

常用管理命令：

systemctl status orcsy          # 看运行状态
sudo systemctl restart orcsy    # 改完 /var/lib/orcsy/config.yaml 后重启
journalctl -u orcsy -f          # 实时看日志
sudo bash deploy/linux/uninstall.sh   # 卸载（数据目录默认保留）

如果服务器开了防火墙，记得放行 5116 端口（或你自定义的端口）。

4.6 安装后检查清单

安装完成后，逐项确认：

5. 第一次启动：把大模型接上

Orcsy 本身不包含 AI 能力，它需要一个「大模型服务」来干活。你需要把服务地址、模型名、密钥告诉它。

5.1 打开设置页

点顶部导航的「项目与设置」，找到第一张卡片「🤖 大模型接入」。

5.2 逐项填写

字段 怎么填 说明
协议 provider 大多数服务选 openai（兼容协议）；Claude 官方或 Anthropic 兼容服务选 anthropic 选错会连不上
模型 model 服务商给你的模型名，例如 deepseek-chat、glm-4-plus、moonshot-v1-32k 可以先点「获取列表」再下拉选择
API 地址 base_url 服务商提供的接口地址，通常以 /v1 结尾 见下方对照表
API Key 服务商控制台生成的密钥，通常以 sk- 开头 只显示掩码，不会明文回显
采样温度 temperature 默认 0.2 即可 越高越发散，写代码建议低一些
最大输出 max_tokens 默认 8192 即可 拉取模型列表后会自动跟随模型上限
上下文窗口 max_context_tokens 默认 131072 即可 同上，按模型规格自动填充
请求超时 timeout_seconds 默认 300 秒 长任务/思考模型可改 600~900；-1 表示不超时
请求侧开启模型思考 默认关闭 只有需要看模型思考过程时才开；不支持的模型不要开

5.3 常见服务怎么填

服务 协议 base_url 模型名示例
DeepSeek openai https://api.deepseek.com/v1 deepseek-chat
智谱 GLM openai https://open.bigmodel.cn/api/paas/v4 glm-4-plus
Kimi（月之暗面） openai https://api.moonshot.cn/v1 moonshot-v1-32k
通义千问 openai 以阿里云控制台为准（通常含 /compatible-mode/v1） qwen-plus
OpenAI openai https://api.openai.com/v1 gpt-4o
Ollama（本机） openai http://127.0.0.1:11434/v1 qwen2.5-coder:14b
Anthropic Claude anthropic https://api.anthropic.com claude-sonnet-4-...

💡 不确定模型名时，先点「获取列表」。如果服务商不支持列表接口（返回 404），直接手动输入模型名即可。

5.4 两个按钮的用处

  • 获取列表：向服务商查询可用模型，成功后「模型」框可以下拉选择，并自动填入上下文窗口和最大输出。
  • 测试连接：发送一条极短的对话，验证「网络 + 密钥 + 模型名」是否都正确。建议每次改完配置都点一次。

5.5 保存

点「保存模型配置」。顶部标题下方会显示当前模型，例如：

v0.18.0 · 模型 deepseek-chat（openai） · 配置 C:\Users\你\AppData\Roaming\Orcsy\config.yaml

如果显示「未配置 api_key」，说明密钥没保存成功，回到设置页检查。

6. 接入你的第一个项目

6.1 新建项目

点右上角「＋ 新建项目」（或设置页「📁 受管项目」里的同名按钮）。

按顺序填写：

  1. 项目名：建议用字母、数字、连字符（也允许下划线），例如 my-app；不要有空格和特殊符号，且不能以符号开头。它会出现在日志和分支名里。
  2. 每轮最多任务数：默认 1。意思是「每一轮扫描，这个项目最多做几个任务」。刚开始建议保持 1，稳定后再加。
  3. 项目路径：点「选择…」选你的项目文件夹，或直接粘贴绝对路径，例如 D:\Repos\my-app。
  4. 任务目录：默认 tasks，保持默认即可。
  5. 指引文件：默认 AGENT.md，保持默认即可。
  6. 工具循环轮数上限：默认 40。AI 做任务时最多「思考—操作」多少轮；填 -1 表示不限制（不建议新手使用）。
  7. 工作分支：可选。留空表示在项目当前分支上工作。
  8. 命令白名单：可选。留空使用默认白名单（python、node、npm、git、dotnet 等常见命令）。
  9. 绑定专属模型：可选。打开后可以给这个项目单独指定模型；不填的字段自动继承全局配置。
  10. 访问权限：默认「跟随全局」。想更安全可以选「变更前询问」。
  11. 覆盖 Agent 工具开关：可选。默认跟随全局，不需要动。
  12. 绑定远程仓库 Issues：可选。想让 GitHub/Gitee/GitLab/Gitea 的 Issue 自动变成任务时再打开。
  13. 技术栈 / 本地运行 / 测试：填完路径后 Orcsy 会自动探测并预填，你可以修改。这些内容会写进 AGENT.md，让 AI 少走弯路。
  14. 启用该项目：保持打开。

点「保存」。你会看到：

  • 项目卡片出现在「看板」页；
  • 项目文件夹里多了 tasks/ 和 AGENT.md（如果原来没有）；
  • 卡片上显示项目路径、任务统计、git 或 非 git 标记。

6.2 项目卡片上的标记

标记 含义
git 项目是 Git 仓库，任务完成后会自动提交、合并，配置了远端还会推送
非 git 项目不是 Git 仓库，Agent 会直接改文件，但不会自动提交
缺指引 项目里没有 AGENT.md，建议点「AGENT.md」补上
自动拉取 Nmin 已开启定时拉取 Issue，每 N 分钟一次
开关 项目启用/停用。停用后调度器会跳过它，配置和文件都保留

6.3 什么是 AGENT.md，为什么它很重要

AGENT.md 是这个项目的「员工手册」。AI 每次做任务前都会先读它。

里面通常写：

  • 项目技术栈（用什么语言、框架）；
  • 怎么本地运行；
  • 怎么跑测试；
  • 代码风格和规范；
  • 哪些事情绝对不能做；
  • 什么情况下应该停下来求助（blocked）。

新建项目时 Orcsy 会自动生成一份英文模板，并根据探测结果填入 Stack / Run / Test。你可以点项目卡片上的「AGENT.md」直接编辑，改成中文、补充项目约定都可以。

💡 想让 AI 表现更稳定，最值得花时间的就是把 AGENT.md 写清楚：测试命令、代码规范、不要碰的目录、完成标准。

6.4 项目级可选设置

在项目卡片点「设置」可以修改：

  • 项目名、路径、任务目录、指引文件；
  • 每轮任务数、轮数上限、工作分支、命令白名单；
  • 专属模型；
  • 访问权限；
  • 工具开关覆盖；
  • 远程仓库绑定与自动拉取间隔；
  • 启用/停用。

修改项目名会同步更新绑定到该项目的技能，不会丢失。

7. 创建和管理任务

7.1 最快的方式：卡片上的快速添加

在「看板」页的项目卡片里：

  1. 在「新任务标题，回车快速添加」输入框里写一句话；
  2. 选择优先级（默认 P2）；
  3. 点「添加」或直接按回车。

任务 ID 会自动生成，格式是 优先级-标题，例如 P2-修复登录页错位。重复时自动加 -2、-3。

7.2 完整方式：新建任务对话框

点项目卡片下方的「新建任务」，可以填写更多信息：

字段 说明
任务 ID 留空自动生成；也可以自己起一个英文短名，例如 fix-login-timeout
优先级 P0 最高，P4 最低
标题 一句话说明要做什么
标签 逗号分隔，例如 bug, ui，只用于分类和展示
指派 留空表示任意 Agent 都可以领；填写项目名则只有对应 Agent 处理
任务描述 Markdown 正文，写现象、复现步骤、验收标准

点「保存」后任务进入 open（待办）状态。

⚠️ 只有「待办」状态的任务可以直接编辑。执行中、受阻、已完成的任务点开是只读查看；想改内容，先点「重新入队」把它变回待办。

7.3 优先级怎么选

优先级 什么时候用 例子
P0 线上事故、阻塞所有人的问题 支付接口 500、程序启动即崩溃
P1 重要功能坏了，或本周必须完成 登录失败、核心流程报错
P2 普通需求、一般 Bug（默认） 加一个筛选框、修复样式错位
P3 可以排期、不着急 补文档、优化日志文案
P4 有空再做 代码清理、体验优化

排序规则：先按优先级 P0 → P4；同一优先级内，按你在看板上拖拽的顺序。受阻后重新入队的任务，下一轮会优先领取。

7.4 任务文件长什么样

用文本编辑器打开 tasks/P2-修复登录页错位.md，会看到：

---
title: 修复登录页错位
priority: P2
status: open
labels: [bug, ui]
assignee:
---

## 现象

在 125% 缩放下，登录按钮溢出卡片右侧。

## 复现步骤

1. Windows 显示设置改为 125%；
2. 打开登录页；
3. 观察按钮位置。

## 验收标准

- [ ] 100% / 125% / 150% 缩放下布局正常
- [ ] 不改变现有登录流程

你可以直接改这个文件，保存后看板下一轮刷新就会显示新内容。

💡 任务正文里不要写密钥、密码、内部地址。任务文件会进入 Git 仓库，可能被提交。

7.5 任务状态与生命周期

open（待办）
  │  Agent 领取
  ▼
in_progress（执行中）
  │
  ├── 完成 ──▶ done（已完成）──▶ 自动移动到 tasks/done/
  ├── 受阻 ──▶ blocked（受阻）──▶ 等你处理，可「重新入队」
  └── 手动停止 ──▶ cancelled（已取消）──▶ 要重跑时把任务文件 status 改回 open
状态 看板显示 你可以做什么
open 待办 编辑、删除、拖拽排序
in_progress 执行中 查看、强制停止、标记完成（不推荐）
done 已完成 查看；自动归档
blocked 受阻 查看原因、重新入队、删除
cancelled 已取消 查看、删除；要重跑时把任务文件里的 status 改回 open（或复制内容新建任务）

7.6 任务列表上的操作

操作 在哪里 作用
点击任务行 看板任务列表 待办任务打开编辑；其它状态只读查看
拖拽任务行 任务列表 调整同一优先级内的顺序，同时决定 Agent 领取顺序
勾选任务 任务行左侧 批量选择
全选本页 列表上方 选中当前页 10 个任务
批量删除 选中后出现 删除选中的任务文件，不可恢复
清空任务（N） 列表上方 删除该项目全部活动任务，不影响已归档
重新入队 受阻/执行中任务 变回待办，下一轮优先领取
标记完成 待办/执行中任务 手动把任务标为完成（不会自动归档）
强制停止 执行中任务 立即中止 AI 循环和正在跑的命令，丢弃临时改动，标为已取消
删除 每个任务行 删除单个任务文件

⚠️ 「删除」「清空」「强制停止」都不可撤销。删除任务文件前建议先确认内容；Git 项目强制停止会丢弃本次任务在临时副本里的改动，非 Git 项目已改的内容会留在目录里。

7.7 已归档任务

任务完成后会自动移动到 tasks/done/。项目卡片底部的「已归档（N）· 点击查看详情」可以展开查看，点任务行只读查看内容。

7.8 写好任务的 5 个技巧

  1. 写清楚「现在是什么样」：报错信息、截图描述、复现步骤。
  2. 写清楚「做成什么样算完成」：用验收标准列表，越具体越好。
  3. 限定范围：告诉它只改哪个页面/模块，不要顺手重构整个项目。
  4. 一次只做一件事：大任务拆成多个小任务，成功率和可审查性都更高。
  5. 提供验证方法：例如「运行 npm test」「打开 /login 页面检查」。

一个反例（太模糊）：

优化一下登录。

一个正例：

登录页在 125% 缩放下按钮溢出卡片。请只调整登录页样式，不改登录逻辑。验收：100%/125%/150% 三种缩放下按钮完整显示，npm run build 通过。

8. 让 Orcsy 开始工作

8.1 两种触发方式

  • 定时调度：程序每隔一段时间自动扫描一次。默认 300 秒，可在设置页改（30~86400 秒）。
  • 立即扫描：点顶部「▶ 立即扫描」，马上执行一轮。适合刚加完任务想立刻看结果。

两者不会重复领取任务：同一时间一个项目只有一个 Agent 在工作。

8.2 看板顶部状态条

标签 含义
调度空闲 / 扫描执行中… 当前有没有在跑扫描
已完成周期 N 从启动到现在跑了多少轮
上次扫描 刚刚 / N 分钟前 最近一次扫描时间
扫描间隔 Ns 当前设置的间隔
项目名：处理 N 任务 上一轮每个项目处理了几个任务

8.3 任务执行时发生了什么

  1. Orcsy 扫描项目 tasks/，挑出 status: open 的任务；
  2. 按优先级和顺序领取一个；
  3. 把状态改成 in_progress；
  4. 如果项目是 Git 仓库，在项目下创建临时工作副本 .worktree-arranger/；
  5. AI 读 AGENT.md 和任务内容，开始读文件、改文件、跑命令；
  6. 每轮操作都会往任务文件的「## 执行进度」追加一行，进程被强杀也不丢；
  7. AI 报告完成后：
    • 成功：系统提交、合并回主分支；配置了远端则推送；任务标 done 并归档；
    • 受阻：丢弃临时副本，任务标 blocked，写明原因；
    • 取消：丢弃临时副本，任务标 cancelled。

Git 项目才有临时副本；非 Git 项目没有这层隔离，Agent 已做的修改会留在项目目录里，受阻/取消后请自行检查或还原。

8.4 看运行日志

看板底部的「运行日志（从新到旧，点击收起）」会显示：

  • 每轮扫描开始/结束；
  • 每个任务的开始/结束、提交号、受阻原因；
  • 模型思考内容（如果开启）会折叠成紫色条目，点开可看。

页面每 5 秒自动刷新。日志同时写入 logs/orcsy.log。

8.5 任务结束后

  • 成功：任务行变「已完成」，进入归档；项目多一条 Git 提交；
  • 受阻：任务行变「受阻」，点开可看「Agent 处理结果」里的原因；
  • 取消：任务行变「已取消」；要重跑就把任务文件里的 status 改回 open。

如果开启了提醒，完成/受阻时会有提示音和托盘气泡；手动停止不会提醒。

10. 进阶功能：审批、技能、Issues、镜像源

10.1 人工审批（访问权限模式）

默认是「完全访问」，AI 做任何操作都不询问。想更安全，可以在设置页改：

模式 适合谁 会询问什么
ask_on_change 变更前询问 第一次用、对 AI 不放心 写文件、改文件、批量改、删文件、移动文件、执行命令
autonomous 自主模式 有经验、只想拦住高风险操作 删文件、移动文件、执行命令
full_access 完全访问（默认） 信任 AI、追求效率 不询问

工作方式：

  1. AI 要做敏感操作时，任务会挂起（操作不执行，零副作用）；
  2. 顶部出现「🔔 待审批 N」；
  3. 点开可以看到：项目、任务、工具、参数预览、已等待时间；
  4. 你可以「批准」或「拒绝」；
  5. 勾选「本任务内始终允许该工具」可以减少重复确认（只对当前任务有效）；
  6. 超过审批超时（默认 30 分钟）没人处理，会自动拒绝，任务不会永久卡住。

拒绝和超时都会告诉 AI「为什么不行」，让它调整方案或按受阻收尾。

10.2 工具开关与命令白名单

工具开关决定 AI 能用哪些能力。默认全开（finish 是结束任务的协议工具，永远可用）。

常见用法：

  • 不想让 AI 联网：关闭 web_fetch；
  • 只让 AI 改代码、不跑命令：关闭 run_command；
  • 只想让 AI 审查、不改文件：关闭写/改/删/移类工具。

命令白名单决定 run_command 能执行哪些命令。默认包含 python、pytest、node、npm、cargo、go、dotnet、git、包管理器、常用只读命令等。关闭某个命令后，AI 调用会被直接拒绝。

项目级可以覆盖全局设置：项目对话框里打开「覆盖 Agent 工具开关」，逐项设置。删除覆盖即回到跟随全局。

10.3 技能库（Skill）

技能是给 AI 的「专项工作手册」。例如：

  • 项目的编码规范；
  • 某个框架的最佳实践；
  • 发布流程；
  • 环境安装指南。

四种来源：

  1. 内置 env-setup：首次启动自动放入，教 AI 在缺少语言/工具链时自动安装；
  2. 扫描 AI 工具：把 ZCode / Claude Code / Codex / OpenCode 等工具里已有的技能批量导入；
  3. 导入本地技能：选择一个包含 SKILL.md 的目录；
  4. 新建技能：在看板里直接写名称、描述、正文。

技能的作用范围：

  • 全局：所有项目都能用；
  • 专属·项目名：只有该项目能用。

注意：

  • 技能存放在数据目录的 skills\ 里，不会写进项目目录；
  • 系统提示词里只放「名称 + 描述」索引，AI 需要时再用 read_skill 读取全文，所以技能多也不会撑爆上下文；
  • 删除外部导入的技能，只是删除 Orcsy 里的副本，原工具目录里的样本还在，可以重新扫描找回；
  • 删除自建技能不可恢复。

10.4 Issues 自动导入

如果你把项目托管在 GitHub / Gitee / GitLab / Gitea，可以让 Issue 自动变成任务。

配置步骤：

  1. 项目「设置」→ 打开「绑定远程仓库 Issues」；
  2. 填仓库 URL，例如 https://github.com/owner/repo；
  3. 选择平台（自托管 GitLab/Gitea 必须手动选）；
  4. 填认证信息：
    • token（推荐；GitHub 只支持 token）；
    • 或账号 + 密码（GitLab / Gitee / Gitea 支持）；
  5. 可选：填自动拉取间隔（分钟，0 表示只手动拉取）；
  6. 保存。

使用：

  • 项目卡片点「拉取 Issues」→ 把 open 状态的 Issue 导入任务队列；
  • 优先级默认 P2；Issue 带 P0~P4 标签时按标签；
  • 任务文件带来源标注，已导入过的（包括已归档）不会重复导入；
  • 单向导入：Orcsy 不会把任务状态写回 Issue。

10.5 镜像源与国内网络

如果你在国内、没有代理，下载依赖可能很慢或失败。Orcsy 提供了三层兜底：

  1. 镜像源测速：设置页「🪞 镜像源管理与测速选源」→ 点「测速全部源」→ 点「应用最快源到环境变量」；
  2. 环境变量：在「Agent 子进程环境变量」里填 GOPROXY、PIP_INDEX_URL、npm_config_registry、HTTP_PROXY 等；
  3. env-setup 技能：AI 发现缺少工具链时，会按技能自动安装；包管理器失败时自动切换国内镜像直下。

镜像源类别包括：Go 安装包、Go 模块代理、npm registry、pip index、Node.js 安装包、JDK、Python 安装包。你可以禁用不想要的源，也可以添加自己的内网镜像。

⚠️ 「应用最快源到环境变量」会覆盖你手动填的同类环境变量。应用后请检查一下文本框内容。

10.6 多项目、并行与专属模型

  • 每个项目一个 Agent，互不干扰；
  • 设置页「并行 Agent 数」大于 1 时，多个项目可以同时执行（1~16）；
  • 同一个项目同一时间只做一个任务；
  • 项目可以绑定专属模型：例如简单项目用便宜模型，复杂项目用强模型；
  • 专属模型只覆盖你填的字段，没填的自动继承全局。

10.7 通知

设置页「🔔 提醒设置」：

  • 提示音：完成播内置「叮咚」音，受阻播内置警示音（音频缺失时回退 Windows 系统音）；
  • 系统通知：托盘气泡，看板没开也能收到；
  • 手动停止（取消）不提醒；
  • 用 --no-tray 启动时没有托盘，系统通知没有渠道。

10.8 自动更新与重启

  • 启动时自动检查更新（可关）；
  • 顶部「检查更新」→ 有新版本时点「更新到 x.y.z」；
  • 更新包在后台静默安装，程序自动重启，页面自动刷新；
  • 装在 Program Files 等系统目录时，会弹一次 UAC 授权；
  • 更新失败会自动回滚，并打开安装日志；
  • 也可以「手动导入本地安装包」：选择 orcsy-update-*.zip，支持同版本覆盖、升级、降级。

10.9 看板登录密码

默认只监听 127.0.0.1，只有本机能访问，不需要密码。

如果你要：

  • 用 --host 0.0.0.0 让局域网访问；
  • 用 Docker / systemd 部署到服务器；
  • 通过反向代理暴露到公网；

必须设置登录密码。非回环地址 + 空密码时程序会拒绝启动；如果绕过这层保护对外暴露，任何能访问端口的人都能操作看板、改配置、启停任务（密钥只显示掩码，但仍可被替换）。

设置位置：

  • 设置页「⏱ 调度与看板」→「看板登录密码」；
  • 或直接编辑 config.yaml 的 web.auth_password。

设置后打开看板会先出现登录页：输入密码 → 点「登录」。顶部右侧会出现「退出」按钮。

行为：

  • 登录后会话有效期 7 天；
  • 程序重启后需要重新登录；
  • 修改密码后所有旧会话立即失效；
  • 鉴权不替代 HTTPS。公网部署请再套一层反向代理（nginx / caddy）上 HTTPS。

10.10 日志、开机自启与端口

日志

  • 看板底部的「运行日志」只显示最近一段，完整日志在数据目录的 logs/orcsy.log；
  • 设置页「⏱ 调度与看板」可以设置：
    • 日志保留（天）：默认 7 天，写满后归档到 logs/archive/，超过天数的旧日志自动清理；0 表示关闭自动清理；
    • 日志总占用上限（MB）：默认 200，活动日志 + 备份 + 归档合计超限时从最旧的删起；0 表示不限制；
  • 保存后立即按新规则执行一次清理。

开机自启

  • 设置页「⚙️ 应用」→ 打开「开机自动启动」；
  • 写入当前用户注册表，不需要管理员权限；
  • 托盘菜单里也有「开机自启动」勾选项；
  • 不想要自启时，关掉开关即可。

看板端口

  • 设置页「⏱ 调度与看板」→「看板端口」；
  • 保存后下次启动生效；
  • 也可以用命令行 --port 8080 临时覆盖；
  • 端口冲突时的行为见 12.1。

10.11 任务审查（Review Agent）：第二个模型把关

Orcsy 支持在任务完成后、合并归档前，由一个独立的审查 Agent（与执行任务的 Agent 不是同一个模型）检查任务成果：对照需求与验收标准抽查实现、（可选）实际跑测试验证。审查通过才合并主分支并归档；不通过则带着问题清单自动返工。

默认状态：审查未启用。 没配置审查模型时一切照旧（任务完成即合并归档）。想开启，只需要给系统配置第二个模型（可以是便宜的小模型）：

  1. 打开设置页「🔍 任务审查（Review Agent）」卡片；
  2. 填写审查模型的 provider / base_url / api_key / model（点「获取模型列表」可拉取候选）；
  3. 保存。审查门即刻对全部项目默认生效（某个项目不想要时，在该项目「设置」→「审查 Agent」里单独关闭）。

硬性规则：审查模型不能与任务模型相同。 任务模型在设置页「大模型接入」配置（项目可绑定专属模型）；审查模型与之同名时保存会被拒绝——两个不同的模型交叉验证，防止「自己审查自己」。

审查是怎么工作的：

  • 任务 Agent 报告完成后，改动先提交到工作分支（还不合并）；
  • 审查 Agent 只读核查代码：对照任务里的验收标准逐条检查，「允许执行测试命令」开关打开时（默认）会实际跑测试验证；
  • 通过 → 自动合并主分支 → 归档到「已完成」；
  • 不通过 → 任务带着审查意见自动返工（意见写在任务正文里，执行 Agent 下轮直接看到）；返工次数默认 2 次（全局可调 1~10，项目可单独设置），用完转「受阻」等人工裁决——此时成果保留在工作分支上，可以人工检视或手动合并；
  • 审查中途程序被关掉也没关系：改动已经提交在分支上，下次启动自动补审，不会重跑任务。

返工与提交： 返工过的任务通过审查后，多次返工的提交会自动收敛为一个提交再合并（「返工通过后收敛提交」开关，默认开），保持主分支历史整洁。

看板上的标记： 任务卡片上 🔍 待审查 表示已完成正在审查或等待补审；🔍 返工 ×N 表示被审查退回过 N 次。项目卡片上会显示「审查开启 / 审查关闭 / 审查模型冲突」状态。

成本提示： 审查每次约消耗 3~8 轮只读调用的 token，在设置页「用量统计」里按审查类单独记录，可与执行消耗分开核算。

10.12 多模型 Agent 项目小组（Project Team）协同

Orcsy 0.22.0 引入了多模型 Agent 项目小组（Project Team）。用户可以自由组合多个不同专长大模型的 Agent 组成研发团队进驻任意项目，完成复杂需求的分工协作：

  • 👑 项目经理（PM）：只读摸底项目代码库与架构，将需求拆解为职责明确的子任务并使用 depends_on_refs 编排 DAG 有向无环依赖图；或对简单单端任务直接调用 reassign_task 转派下游。
  • ⚙️ 后端 / 🎨 前端开发工程师：在按任务隔离的 Git Worktree 沙盒中专注本端编码与单测，Prompt 自动透传前置依赖任务的交付物摘要（接口契约）。
  • 🧪 测试工程师（QA）：拉起本地服务与无头/桌面浏览器进行端到端联调测试；发现缺陷调用 report_bug 派发 Bug 修复任务，原测试任务自动挂靠依赖并进入等待回归状态，待前后端修复后自动唤醒 QA 开展多轮回归测试。
  • 🛡️ 强制 Worktree 沙盒隔离 + 人工把关最终提交：所有写代码角色按任务在独立 .worktree-arranger/<task_id> 沙盒中编码，通过审查后仅增量合入主分支工作区（未提交状态），默认绝不自动执行 git commit 与 git push，最终提交权 100% 留给人把关！
  • ⚡ 同周期链式推进（chain_within_cycle）：依赖解锁后毫秒级连续接棒推进下一阶段，单个需求无需跨越多个 300 秒调度周期即可完整闭环。
  • 👥 双层配置复用：全局设置页「👥 Agent 角色预设池」一次配置各角色专属模型 + 项目设置弹窗自由引用与局部技术栈微调。

10.13 本地调试与 Chromium 浏览器自动化（Local Debug）

针对 Web 与 API 项目，Orcsy 内置了基于 CDP 协议的本地调试工具链（测试工程师 QA 默认开启，开发角色按需可选）：

  • Chromium 浏览器自动化（browser_*）：通过纯 Python CDP 直连本地安装的 Google Chrome 或 Microsoft Edge（零外部 driver 依赖），支持元素结构化文本快照、按 ref 寻址点击与输入、页面等待、截图落盘及 Console/Network 日志监听；
  • 开发服务管理（dev_server_*）：任务中后台常驻启动 dev server（自动分配空闲端口并等待就绪），任务结束自动清理释放子进程；
  • 本地接口调试（http_request）：受控放行本地/局域网 HTTP API 调试（Cookie 会话保持，受主机白名单严格约束，杜绝内网穿透）。

11.2 备份

建议备份：

  • 数据目录（配置、技能、日志、用量）；
  • 各项目的 tasks/ 和 AGENT.md；
  • 项目代码本身（用 Git 远端备份）。

config.yaml 里有 API Key，不要上传到公开仓库、不要发给别人。

11.3 迁移到另一台电脑

  1. 在新电脑安装 Orcsy；
  2. 关闭程序；
  3. 把旧电脑的数据目录复制到新电脑对应位置；
  4. 打开 config.yaml，检查 projects[].path 是否要改成新电脑的路径；
  5. 启动程序，打开看板确认项目和任务都在。

也可以用环境变量 ORCSY_DATA_DIR 把数据目录整体改到别的位置（例如移动硬盘）。

12. 常见问题与排查

12.1 看板打不开 / 端口被占用

  • 确认程序在运行（托盘图标是否还在）；
  • 默认地址是 http://127.0.0.1:5116；
  • 如果端口被别的程序占用：
    • 用配置端口启动：程序会自动换一个空闲端口，控制台会提示新端口；
    • 用 --port 显式指定：如果被占用会直接报错退出（尊重你的选择）；
  • 如果你之前开过另一个 Orcsy，会提示「已有看板在运行」，先关掉旧的。

12.2 任务一直「受阻」

点开任务看「Agent 处理结果」和运行日志，常见原因：

  • 模型请求失败（超时、429、500、502、503、504）：程序会自动退避重试；仍失败才标受阻；
  • AI 判断信息不足、需要人工决策；
  • 审批被拒绝或超时；
  • 测试命令不存在或环境缺少工具链；
  • 合并冲突。

处理：

  1. 看日志定位原因；
  2. 修改任务描述，补充信息或缩小范围；
  3. 点「重新入队」，下一轮会优先重跑。

12.3 审批没人处理会卡死吗

不会。超过审批超时（默认 30 分钟）会自动拒绝，AI 会收到拒绝原因并调整方案或按受阻收尾。

12.4 中途关机 / 强杀进程，任务会丢吗

不会丢任务文件。执行进度会实时写进任务文件的「## 执行进度」；意外中断的任务在下次启动时会被重置回待办，重新排队。

12.5 国内网络拉依赖失败

按顺序尝试：

  1. 设置页「镜像源管理与测速选源」→ 测速 → 应用最快源；
  2. 在「Agent 子进程环境变量」里配 GOPROXY / PIP_INDEX_URL / npm_config_registry / HTTP_PROXY；
  3. 打开「任务启动时自动把缺失的工具目录写入用户 PATH」；
  4. 如果公司有内网镜像，在镜像源页添加并测速。

12.6 支持哪些模型

  • OpenAI 兼容协议：DeepSeek、智谱 GLM、Kimi、通义、OpenAI、Ollama、vLLM 等；
  • Anthropic 协议：Claude 官方及兼容服务。

用「获取列表」和「测试连接」验证配置。

12.7 外网 / 服务器部署要注意什么

  • 看板默认只监听 127.0.0.1，本机使用最安全；
  • 对外暴露必须设置 web.auth_password；
  • 非回环地址 + 空密码会拒绝启动；
  • 鉴权不替代 TLS，公网建议反向代理 + HTTPS；
  • 不要把 config.yaml 提交到仓库。

12.8 合并冲突 / 推送失败

  • 提交和合并由系统执行，AI 不直接操作 Git；
  • 合并冲突时会保留 arranger/<项目名> 分支，任务标受阻，等人工处理；
  • 推送失败通常是凭据问题：HTTPS 用 token，SSH 用密钥；
  • 处理完后点「重新入队」。

12.9 Windows 更新需要管理员权限吗

  • 装在用户可写目录：全程零 UAC；
  • 装在 Program Files 等系统目录：会弹一次 UAC，点「是」继续；取消则不更新，程序照常运行；
  • 更新失败会自动回滚并保留安装日志。

12.10 能不用看板，只当命令行调度器吗

可以：

orcsy run --config config.yaml          # 持续调度
orcsy run --config config.yaml --once   # 单轮，适合 Windows 计划任务 / cron

看板模式也可以加 --no-sched，只保留手动「立即扫描」。

12.11 托盘图标没出现 / 不想要托盘

  • 用 --no-tray 启动；
  • Docker 内自动关闭托盘；
  • 没有托盘不影响看板，直接访问地址即可；但系统通知也没有渠道。

12.12 任务完成后代码去哪了

  • Git 项目：自动提交并合并回主分支；配置了远端会推送；
  • 非 Git 项目：直接改在项目目录里，不提交；
  • Git 项目受阻/取消：临时副本被丢弃，项目主目录不变；
  • 非 Git 项目受阻/取消：没有临时副本，Agent 已经做的修改会留在项目目录里，需要你自行检查或还原。
