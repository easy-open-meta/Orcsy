完整安装教程

先按场景选方式（各方式命令速查见主页「快速开始」标签页）：

场景推荐方式
Windows 个人电脑（最省事）Windows 安装包：托盘常驻、开机自启、程序内一键自更新，自带运行环境无需装 Python
想看 / 改源码、参与开发源码运行（uv，首次运行自动准备 Python 3.11+）
服务器 / NAS / 不想装运行环境Docker Compose
Linux 服务器系统级常驻systemd 服务（install.sh 一键装）
  • 通用前置：一个可用的大模型 API Key（OpenAI 兼容协议或 Anthropic）；受管项目建议是 git 仓库——Agent 的改动全部发生在独立 worktree，系统统一提交合并（非 git 项目也能跑，只是没有版本控制整合）；
  • 配置不用手写：首次启动自动生成（Windows 在 %APPDATA%\Orcsy、Docker 在 ./orcsy-data、Linux 在 /var/lib/orcsy），模型密钥等都能在看板「项目与设置」页可视化填写；
  • 数据不进项目目录：配置、技能库、日志、用量台账都集中在数据目录，受管项目里只新增 tasks/ 与 AGENT.md。

① Windows 安装包（推荐）

# 1. 下载 orcsy-setup-<版本>.exe（GitHub / Gitee Releases）→ 按向导安装
#    可勾选「初始化示例任务」在数据目录放示例模板；config.yaml 首次启动自动生成
# 2. 开始菜单/桌面打开「任务编排系统」→ 浏览器自动打开看板（127.0.0.1:5116）
# 3. 「项目与设置」页：填 llm.api_key / base_url / model → 新建项目（绝对路径）
# 4. 看板新建任务，或往项目 tasks/ 放 .md 任务文件 → 点「立即扫描一轮」
  • 升级：托盘菜单 / 看板顶栏「检查更新」一键静默升级并自动重启。装在用户可写目录全程零 UAC；装在 Program Files 等系统目录会弹一次 UAC 授权（取消则不更新、程序照常运行），失败自动回滚并留安装日志；
  • 卸载：安装包自带卸载器，可选是否一并删除用户数据（%APPDATA%\Orcsy）。

② 源码运行

git clone https://github.com/easy-open-meta/Orcsy.git orcsy && cd orcsy
uv sync                             # 本机需有 uv；首次运行自动准备 Python 3.11+
uv run orcsy init --dir run         # 生成 run/config.yaml 与任务/指引模板
uv run orcsy validate --config run/config.yaml
uv run orcsy web --config run/config.yaml
  • 不想常驻时用外部调度：uv run orcsy run --config run/config.yaml --once（或配置 scheduler.run_once: true），配 Windows 计划任务 / cron 触发单轮；
  • 常用启动参数：--port 换端口、--host 0.0.0.0 对外暴露（务必配登录密码）、--no-tray 关托盘、--no-browser 不自动开浏览器、--no-sched 关定时调度（仅手动「立即扫描」）。

③ Docker Compose（服务器 / NAS）

docker compose up -d --build        # 数据落在 ./orcsy-data，受管仓库放 ./projects
  • 镜像基于 Python 3.12 slim + git，多阶段 uv 构建按 uv.lock 可复现，非 root 运行、tini 转发信号；容器内自动关闭托盘与自动开浏览器；
  • 项目路径必须写容器内路径 /projects/<项目名>（对应宿主 ./projects/<项目名>，需是 git 仓库）；
  • 推送凭据：HTTPS 把 token 写进远端 URL，或按 docker-compose.yml 注释只读挂载 ~/.ssh 并设 GIT_SSH_COMMAND；提交身份默认 Orcsy Agent <orcsy@localhost>，可用 ORCSY_GIT_NAME / ORCSY_GIT_EMAIL 覆盖；
  • 受管项目需要 node 等额外工具链时，按 Dockerfile.custom 叠加镜像（apt-get install 后改 compose 的 image）；
  • 端口映射到公网 / NAS 务必先设置 web.auth_password。

④ Linux systemd（系统级常驻）

sudo bash deploy/linux/install.sh   # 需 root：自动装 uv、建专用用户、装服务并启动
systemctl status orcsy              # 运行状态
sudo systemctl restart orcsy        # 改完 /var/lib/orcsy/config.yaml 后重启生效
journalctl -u orcsy -f              # 跟踪日志（文件日志在 /var/lib/orcsy/logs/）
  • 布局：/opt/orcsy 程序与虚拟环境、/var/lib/orcsy 数据目录（config.yaml / skills / logs）、/srv/orcsy-projects 受管仓库（项目路径写 /srv/orcsy-projects/<项目名>）；
  • 不想用 systemd 时可手动前台运行（数据目录默认 ~/.orcsy）：uv sync --no-dev && uv run orcsy web --host 0.0.0.0 --no-tray --no-browser；
  • 卸载：sudo bash deploy/linux/uninstall.sh（数据目录与受管仓库默认保留，按脚本提示手动清理）。

常见问题 Q&A

问题解答
看板打不开 / 端口被占用？看板默认 127.0.0.1:5116；显式指定的端口被占用会直接报错退出（不会静默换口）。改 web.port（或 --port），或释放占用进程后重启。
任务一直「受阻」？常见三类原因：模型请求最终失败（超时 / 429 / 5xx 已自动退避重试，仍失败才判 blocked）、Agent 判断无法继续主动受阻、审批被拒或超时。看「运行日志」定位；一键「重新入队」后下轮插队重跑。
审批没人处理会卡死吗？不会。挂起超时（默认 30 分钟，可配 1~1440）自动拒绝，拒绝意见会反馈给模型调整方案，任务不会永久挂起。
中途关机 / 强杀进程，任务会丢吗？执行进度逐轮实时写回任务文件的「执行进度」节，已完成轮次不丢；下次启动自动把中断任务重置回 open 继续排队。
国内网络拉依赖失败？三件套兜底：设置页「镜像源测速」选最快源、env.vars 注入 GOPROXY / HTTP_PROXY / PIP_INDEX_URL、env-setup 技能无代理时自动切国内镜像直下（零管理员权限、用户级 PATH 即装即用）。
支持哪些模型？怎么验证配对了？OpenAI 兼容协议（DeepSeek / GLM / Kimi / 通义 / Ollama / vLLM…）与 Anthropic 协议；设置页「拉取模型列表」「测试连通性」一键验证，按所选模型自动填充上下文规格。
外网 / 服务器部署要注意什么？看板默认只监听 127.0.0.1 且无鉴权；对外暴露必须设置 web.auth_password（否则任何能访问端口的人可全权操作，还能看到 api_key）。会话 7 天有效、程序重启后需重登；鉴权不替代 TLS，公网建议再套一层反向代理上 HTTPS。
配置 / 日志 / 技能都存在哪？Windows 在 %APPDATA%\Orcsy，Docker 在 ./orcsy-data（容器内 /data），Linux 在 /var/lib/orcsy；含 config.yaml、skills/、logs/ 与用量台账，不写入受管项目目录。
合并冲突 / 推送失败怎么处理？提交与合并由系统执行；冲突时保留 Agent 分支等人工介入，不会自动强改。推送凭据用 HTTPS token（写进远端 URL）或 SSH key。
Windows 升级需要管理员权限吗？装在用户可写目录时全程零 UAC 静默升级；装在 Program Files 等系统目录会弹一次 UAC（取消则不更新、程序照常运行）；升级失败自动回滚并留安装日志。
能不开看板、只当命令行调度器用吗？可以：orcsy run 持续调度，orcsy run --once 单轮（配 cron / 计划任务，或 scheduler.run_once: true）；看板模式也可加 --no-sched 关定时调度、只手动触发。
托盘图标没出现 / 不想要托盘？用 --no-tray 启动（Docker 内自动关闭）；看板功能不受影响，直接访问 127.0.0.1:5116。

任务文件

每个任务一个 Markdown 文件，放在项目的 tasks/ 目录，文件名即任务 ID。YAML frontmatter 写元信息，正文写需求 / 现象 / 验收标准：

---
title: 修复登录页在 125% 缩放下的布局错位
priority: P1            # P0~P4，数字越小越优先
status: open            # open / in_progress / done / blocked / cancelled
labels: [bug, ui]
assignee: my-app        # 可选：只允许指定项目的 Agent 领取
---

## 现象
125% 缩放时登录按钮溢出卡片…

## 验收标准
- 100% / 125% / 150% 缩放下布局正常
  • 状态机：open → in_progress → done / blocked / cancelled；done 自动归档到 tasks/done/；
  • 执行进度实时写回任务文件的「执行进度」节——进程被强杀也不丢；意外中断的任务下次启动自动重置回 open；
  • 看板拖拽排序落盘 frontmatter 的 order 字段：Agent 领取顺序优先级 P0~P4 始终优先，同一优先级内按 order（未排序的排在同 P 已排序任务之后，删除该行回到自动排序）；
  • 每个项目的 AGENT.md 是该项目的最高行为准则（技术栈、运行/测试命令、编码规范），新建项目时可按探测出的技术栈自动生成。

Agent 工具清单（14 个，除 finish 外逐个可开关）

工具作用类型
list_dir列出项目文件结构（自动忽略 .git / node_modules 等）只读
read_file读文件（按行分页，超长自动截断）只读
grep正则搜索代码（glob 过滤）只读
find_files按文件名 glob 查找（如 *.py）只读
read_skill读取技能库中某个技能的全文只读
web_fetch抓取公网 URL 正文（HTML 剥标签；内网/回环地址一律拒绝，SSRF 防护）只读
speedtest_mirrorsHTTP 测速内置/自定义镜像源，按各类别给出「最快优先」排序（结果与看板共享）只读
write_file创建 / 整体重写文件变更
edit_file精确文本替换（old_string 须唯一匹配）变更
multi_edit同一文件一次多处替换（全有或全无，失败不落盘）变更
delete_file删除文件；删目录须显式 recursive: true高风险
move_file移动 / 重命名（目标已存在须 overwrite: true）高风险
run_command执行白名单命令（python / pytest / node / cargo / go / dotnet / git / uv、winget / scoop 等包管理器、powershell / curl / tar / setx 镜像直下与 PATH 注册、ls / cat / grep / where 等只读探测统计…）；缺工具链时按 env-setup 技能自动安装（需过审批），新装工具立即可用高风险
finish给出结构化结论（completed / blocked / cannot_do + 摘要 + 提交信息）协议

工具开关支持全局默认 + 每项目覆盖（看板设置页与项目对话框可视化编辑，或配置文件 tools: / projects[].tools:）；被禁工具不会下发给模型，执行层兜底拦截。finish 为任务结束的协议工具，始终可用。

访问权限模式（人工审批）

模式语义挂起等待批准的操作
ask_on_change变更前询问全部变更类：write / edit / multi_edit / delete / move / run_command
autonomous自主模式（有风险时询问）仅高风险：delete_file / move_file / run_command
full_access完全访问（减少确认次数，默认）无——与历史行为一致
  • 命中审批的操作不执行、零副作用，任务线程挂起；看板顶栏出现「🔔 待审批」，任务行标注「⏸ 待审批」；
  • 批准 / 拒绝 / 「本任务内始终允许该工具」三种响应；超时（默认 30 分钟，可配）自动拒绝，任务不会永久挂起；
  • 全局 permissions.mode + 项目级 permission_mode 覆盖；拒绝与超时都会反馈给模型调整方案或按 blocked 收尾，全程进度留痕。

配置速查

配置项说明
llm.*模型接入：provider（openai 兼容 / anthropic）、api_key、base_url、model、temperature、max_tokens、上下文窗口、思考开关、超时
scheduler.*扫描间隔（默认 300s）、并行 Agent 数（1~16）、run_once 单轮模式
web.*看板监听地址/端口（默认 127.0.0.1:5116）、自动开浏览器、auth_password 登录鉴权（外网部署务必设置）
tools / permissions全局工具开关（未列出默认启用）；全局访问权限模式与审批超时
env / mirrorsAgent 子进程环境变量注入（GOPROXY / HTTP_PROXY / PIP_INDEX_URL 等，国内拉依赖兜底，不允许覆盖 PATH）；镜像源管理：7 类内置 + 自定义源、逐个禁用，测速选源
projects[]name / path / enabled / tasks_dir / guide_file / 每轮任务数 / 轮数上限（-1 不设上限）/ allowed_branch / allowed_commands，以及 llm、repo（Issues）、tools、permission_mode 四个按项目覆盖项
update.*Gitee 自更新源仓库 / 私有令牌 / 启动自动检查
notify.*任务结束提醒：完成/受阻时提示音 + 托盘气泡系统通知（默认全开，手动停止不提醒），看板设置页「🔔 提醒设置」可视化编辑
logging.*级别、文件路径、保留天数（写满 N 天自动归档清理）

模型接入与安全边界

  • OpenAI 兼容协议覆盖 DeepSeek / GLM 智谱 / Kimi / 通义 / OpenAI / Ollama / vLLM 等，另支持 Anthropic 协议；设置页可拉取模型列表、一键测试连通性、按所选模型自动填充上下文规格；
  • 文件工具禁锢在项目根（worktree）内，绝对路径与 ../ 穿越一律拒绝；命令执行有白名单（可按项目自定义）；
  • git 提交 / 合并 / 推送由系统执行，Agent 无权操作版本控制；合并冲突时保留分支等人工介入；
  • 看板开启 web.auth_password 后所有页面与 API 需先登录（HttpOnly 会话、防爆破延迟）；鉴权不替代 TLS，公网部署建议再套一层反向代理上 HTTPS；
  • 国内网络适配：镜像源 HTTP 测速选源（最快源写入 Agent 子进程环境变量）、env.vars 代理/镜像变量注入、env-setup 缺环境自安装（无代理时自动切国内镜像直下）三件套，拉依赖失败不再卡死任务。
