让 AI Agent
按任务清单自动干活

Orcsy 是一个 AI Agent 任务编排系统：把需求与 Bug 写成 Markdown 任务清单， 支持单兵或多模型 Agent 项目小组（PM、后端、前端、测试）进驻协作；Agent 在独立 Git Worktree 沙盒中真实改代码、跑联调测试，改动安全落地主工作区，最终代码提交完全由人工把关—— 全程由 Web 看板可视化掌控。

Windows 一键安装包 orcsy-setup-*.exe · 在线更新包 orcsy-update-*.zip · 也支持 docker compose up 与 systemd / 源码运行 · ⬇ 前往下载

Why Orcsy

产品优势

不是一个聊天窗口，而是一支「按清单干活的 AI 研发小队」：角色协同、真实执行、安全可控、全程可视。

👥

多模型 Agent 项目小组（Project Team）

自由编排专业角色进驻项目：👑 项目经理 PM（只读摸底、拆解 DAG 任务或直派）、⚙️ 后端 / 🎨 前端专职开发（专注本端编码与单测）、🧪 测试工程师 QA（前后端真机联调与 Bug 提单）。同周期链式推进，下游自动继承上游接口契约。

🛡️

Worktree 沙盒隔离 + 人工把关最终提交

所有写代码任务在独立 .worktree-arranger/ 沙盒中编码，通过审查后仅增量合入主分支工作区（未提交态），默认绝不擅自执行 git commit 与 push，最后提交权 100% 留给人把关，杜绝代码互踩与脏提交。

🌐

本地 Chromium 浏览器与服务调试

纯 Python CDP 协议直连本地 Chrome / Edge 浏览器，进行页面结构化快照、按 ref 点击输入、截图落盘与控制台/网络日志监听；配合 dev_server_* 动态端口服务起停与 http_request 本地接口调试，构成完整联调闭环。

🛠️

工具能力与命令白名单三级分组

设置页按四大标签（工具能力 / 命令行白名单 / 本地调试 / 权限与环境）三级分层；9 大技术生态（Python、Node、编译语言等）结构化管理 90+ 默认白名单命令，支持一键「全选/全关」与即时搜索过滤，标注安全风险等级。

🤖

每项目专属 Agent 或小组

独立的 AGENT.md 行为准则、任务清单与对话上下文；支持绑定专属模型或多模型小组成员，多 Agent 并行处理不同项目与无依赖任务。

🧾

Markdown 任务清单与 DAG 依赖

一个任务一个 .md 文件，优先级、状态、角色指派与 depends_on 依赖关系都写在 frontmatter 里；Git 友好、可版本化，支持有向无环图依赖就绪调度与环依赖死锁拦截。

🔍

独立审查 Agent（合并前把关）

任务完成先提交到工作分支，由另一个模型只读审查：对照验收标准抽查实现、可实际跑测试验证；通过才放行合并，不通过带着问题清单自动返工（次数可调，返工通过后可选 --squash 收敛提交），杜绝「自己审自己」。

🔒

真实执行，安全禁锢

文件工具锁死在项目根内（路径穿越直接拒绝）、命令白名单、工具轮数上限、上下文成本自动裁剪——放开手让它跑，也出不了圈。

🛡️

三档访问权限 + 人工审批

变更前询问 / 自主模式 / 完全访问，全局默认、按项目覆盖。敏感操作挂起等看板批准，超时自动拒绝，任务不会永久卡住，全程进度留痕。

⚡

国内镜像测速选源

内置 7 类 19 个镜像源（清华 TUNA / 阿里云 / 七牛 goproxy.cn / npmmirror 等），看板一键 HTTP 测速、「哪个快用哪个」，最快源自动写入 Agent 子进程环境变量；支持自定义源与逐个禁用。

🧰

缺环境自动装（env-setup）

遇到缺失的语言/工具链，Agent 按内置技能走「预检 → 幂等安装 → 会话修复 → 验证」闭环：包管理器优先，无代理网络自动切国内镜像直下（零管理员权限、用户级 PATH 即装即用）；安装命令同样要过人工审批。

🖥️

Web 可视化看板

单文件页面零依赖：项目/任务/归档/进度/日志一屏掌握，活动项目动态过滤、待人工提交把关弹窗（查看未提交文件清单并一键确认 commit/push）、任务拖拽排序，模型接入、技能库、调度参数全部图形化配置；深浅双主题，5 秒自动刷新。

📊

用量台账与热力图

「用量」页签统计总体、各项目及按 Agent 角色（PM / 后端 / 前端 / 测试 / 审查）的详细任务数/轮数/输入输出 tokens，近 12 周 GitHub 风格用量热力图，任务级台账持久化在 usage.jsonl，重启不丢。

🐙

仓库 Issues 一键转任务

绑定 GitHub / Gitee / GitLab / Gitea 仓库（含自托管），open Issue 自动导入任务队列（标签映射优先级、归档去重），支持定时自动拉取。

📚

技能库（Skill）

导入本地技能目录、看板新建，或一键扫描 ZCode / Claude Code / Codex 等工具的用户级技能批量导入；提示词只注入索引，全文按需读取，不撑爆上下文。

🔄

程序自更新

从 Gitee Release 检查/下载/一键静默升级并自动重启；用户可写目录零 UAC，Program Files 自动走一次 UAC 提权兜底，失败自动回滚并留安装日志。

🔔

任务结束提醒

任务完成/受阻时播程序内置提示音（完成「叮咚」/ 受阻警示音）并弹托盘气泡系统通知，看板没开也能收到；手动停止不打扰，提示音/系统通知可在设置页独立开关。

🔐

看板登录鉴权

一个密码即可给看板加上登录门（HttpOnly 会话、防爆破延迟、改密即踢旧会话），配合 Docker / 服务器部署安全暴露到外网。

🐳

多平台部署

Windows 安装包（托盘常驻 + 开机自启）、Docker Compose（非 root、tini 信号处理）、Linux systemd（崩溃自动拉起）、纯源码 uv 运行，四种姿势全支持。

How it works

工作原理

从一条 Markdown 需求到一次干净的成果交付，全程无人值守协同、最终提交由人把关。

1. 下发需求

往项目 tasks/ 放一个 .md，或在看板/Issues 一键生成需求描述与验收目标。

2. PM 调研与拆分

项目经理 Agent 只读调研代码架构，拆解为后端、前端、联调子任务并使用 DAG 编排依赖，或直接指派责任角色。

3. 前后端分工开发

开发 Agent 在按任务隔离的 Worktree 沙盒内专注编码与单测，自动继承上游交付的接口契约，无依赖任务可安全并行。

4. 独立审查门把关

改动先提交到沙盒分支，独立审查 Agent（与开发模型不同的第二个模型）对照验收标准只读核查、跑测试实测，通过才放行。

5. QA 前后端联调验收

测试 Agent 拉起服务与本地浏览器真机测试，发现缺陷通过 report_bug 提单并自动挂靠回归依赖，修复后自动唤醒回归复测。

6. 安全落地与人工把关

成果安全增量合入主分支工作区（未提交状态，不自动 commit/push），由人工最终检查 git diff 并亲自确认提交与推送！

Quick Start

快速开始

四种安装方式，最快一分钟跑起来。

下载 orcsy-setup-<版本>.exe 按向导安装；配置首次启动自动生成，看板里填模型密钥即可。

# 1. 运行安装包（可勾选「初始化示例任务」）
orcsy-setup-0.18.0.exe

# 2. 打开看板（浏览器自动打开），在「项目与设置」页：
#    填写 llm.api_key / base_url / model（OpenAI 兼容协议，覆盖
#    DeepSeek / GLM / Kimi / 通义 / Ollama / vLLM 等），再新建项目

# 3. 新建任务或往项目 tasks/ 放任务文件，点「立即扫描一轮」
# 配置文件位于 %APPDATA%\Orcsy\config.yaml（本地实体，不受 OneDrive 干扰）
GitHub Releases Gitee Releases

需要本机有 uv；首次运行自动准备 Python 3.11+ 环境。

# 1. 克隆并同步依赖
git clone https://github.com/easy-open-meta/Orcsy.git orcsy && cd orcsy
uv sync

# 2. 初始化运行目录（生成 config.yaml 与模板）
uv run orcsy init --dir run

# 3. 编辑 run/config.yaml：填 api_key/base_url/model，projects 指向你的项目；
#    在每个受管项目里放 AGENT.md 与 tasks/*.md（可从模板复制）

# 4. 校验配置与任务清单
uv run orcsy validate --config run/config.yaml

# 5. 启动 Web 看板（含定时调度，自动打开浏览器）
uv run orcsy web --config run/config.yaml

# 也可以纯 CLI 持续调度 / 试运行一轮（供外部 cron 或计划任务触发）
uv run orcsy run --config run/config.yaml
uv run orcsy run --config run/config.yaml --once

镜像基于 Python 3.12 slim，多阶段 uv 构建、按 uv.lock 可复现；应用以非 root 用户运行。

# 1. 构建并启动（数据落在 ./orcsy-data，受管仓库放 ./projects）
docker compose up -d --build

# 2. 打开看板 http://localhost:5116，在「项目与设置」页填写 llm.api_key，
#    项目路径指向容器内挂载点 /projects/<项目名>（需是 git 仓库）

# 外网部署务必设置看板登录密码（web.auth_password）

系统级服务：专用用户运行、开机自启、崩溃自动拉起。

# 上传/克隆源码后，在仓库根目录执行（需要 root；
# 自动装 uv、建用户、装服务并启动）
sudo bash deploy/linux/install.sh

# 打开看板 http://<服务器IP>:5116，填写 api_key 并新建项目
# （路径填 /srv/orcsy-projects/<项目名>）

systemctl status orcsy            # 运行状态
sudo systemctl restart orcsy      # 改配置后重启生效
journalctl -u orcsy -f            # 跟踪服务日志
