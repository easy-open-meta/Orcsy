让 AI Agent
按任务清单自动干活

Orcsy 是一个 AI Agent 任务编排系统：把需求与 Bug 写成 Markdown 任务清单， 每个项目由一个专属 Agent 定时领取、真实改代码、跑测试，改动在独立 git worktree 中完成后自动提交合并—— 全程由 Web 看板可视化掌控。

Windows 一键安装包 orcsy-setup-*.exe · 在线更新包 orcsy-update-*.zip · 也支持 docker compose up 与 systemd / 源码运行 · ⬇ 前往下载

Why Orcsy

产品优势

不是一个聊天窗口，而是一支「按清单干活的 AI 开发小队」：任务驱动、真实执行、安全可控、全程可视。

🤖

每项目一个专属 Agent

独立的 AGENT.md 行为准则、任务清单与对话上下文；支持绑定专属模型（部分覆盖全局配置），多 Agent 并行处理不同项目。

🧾

Markdown 任务清单驱动

一个任务一个 .md 文件，优先级、状态、验收标准都写在 frontmatter 里；Git 友好、可评审、可被任何编辑器管理，Agent 按 P0~P4 排队领取，看板拖拽排序落盘 order、同优先级内生效。

🌿

git worktree 隔离 + 自动合并

Agent 的全部改动发生在独立 worktree，不碰主工作区；报告完成后系统统一 commit → merge → push，冲突时保留分支等人工介入。提交权不在模型手里。

🔒

真实执行，安全禁锢

文件工具锁死在项目根内（路径穿越直接拒绝）、命令白名单、工具轮数上限、上下文成本自动裁剪——放开手让它跑，也出不了圈。

🛡️

三档访问权限 + 人工审批

变更前询问 / 自主模式 / 完全访问，全局默认、按项目覆盖。敏感操作挂起等看板批准，超时自动拒绝，任务不会永久卡住，全程进度留痕。

🛠️

14 个内置工具，逐个可开关

读写/编辑/批量替换/删移文件、正则与文件名搜索、白名单命令、联网取正文（SSRF 防护）、技能读取、镜像源测速……全局 + 每项目双层开关，只读项目轻松实现。

⚡

国内镜像测速选源

内置 7 类 19 个镜像源（清华 TUNA / 阿里云 / 七牛 goproxy.cn / npmmirror 等），看板一键 HTTP 测速、「哪个快用哪个」，最快源自动写入 Agent 子进程环境变量；支持自定义源与逐个禁用。

🧰

缺环境自动装（env-setup）

遇到缺失的语言/工具链，Agent 按内置技能走「预检 → 幂等安装 → 会话修复 → 验证」闭环：包管理器优先，无代理网络自动切国内镜像直下（零管理员权限、用户级 PATH 即装即用）；安装命令同样要过人工审批。

🖥️

Web 可视化看板

单文件页面零依赖：项目/任务/归档/进度/日志一屏掌握，执行中任务可强制停止、任务可拖拽排序，模型接入、技能库、调度参数全部图形化配置；深浅双主题，5 秒自动刷新。

📊

用量台账与热力图

「用量」页签统计总体与各项目的任务数/轮数/输入输出 tokens，git 提交热力图风格的近 12 周用量图（色深=当日 tokens，悬停看单日明细），任务级台账持久化在 usage.jsonl，重启不丢。

🐙

仓库 Issues 一键转任务

绑定 GitHub / Gitee / GitLab / Gitea 仓库（含自托管），open Issue 自动导入任务队列（标签映射优先级、归档去重），支持定时自动拉取。

📚

技能库（Skill）

导入本地技能目录、看板新建，或一键扫描 ZCode / Claude Code / Codex 等工具的用户级技能批量导入；提示词只注入索引，全文按需读取，不撑爆上下文。

🔄

程序自更新

从 Gitee Release 检查/下载/一键静默升级并自动重启；用户可写目录零 UAC，Program Files 自动走一次 UAC 提权兜底，失败自动回滚并留安装日志。

🔔

任务结束提醒

任务完成/受阻时播提示音（Windows 系统音）并弹托盘气泡系统通知，看板没开也能收到；手动停止不打扰，提示音/系统通知可在设置页独立开关。

🔐

看板登录鉴权

一个密码即可给看板加上登录门（HttpOnly 会话、防爆破延迟、改密即踢旧会话），配合 Docker / 服务器部署安全暴露到外网。

🐳

多平台部署

Windows 安装包（托盘常驻 + 开机自启）、Docker Compose（非 root、tini 信号处理）、Linux systemd（崩溃自动拉起）、纯源码 uv 运行，四种姿势全支持。

How it works

工作原理

从一条 Markdown 任务到一次干净的 git 提交，全程无人值守、步步留痕。

写任务

往项目 tasks/ 放一个 .md：标题、优先级、现象与验收标准；或在看板/Issues 一键生成。

调度领取

调度器定时扫描各项目，按 P0~P4 排序领取待办（同优先级内按手动 order，尊重 assignee、每轮限额），任务置为进行中。

Agent 工具循环

专属模型在独立 worktree 里用 14 个禁锢工具探索、改码、跑测试，缺工具链自动按 env-setup 技能安装修复；敏感操作按权限模式挂起等人工审批。

提交合并

Agent 报告完成后，系统在 worktree 内按 Conventional Commits 提交，--no-ff 合并回主分支并推送远端。

回写归档

结果（摘要/轮数/token/变更文件）写回任务文件并归档到 done/，token 用量记入台账热力图；受阻任务标 blocked 等人处理，完成/受阻即时弹提示音与系统通知。

Quick Start

快速开始

四种安装方式，最快一分钟跑起来。

下载 orcsy-setup-<版本>.exe 按向导安装；配置首次启动自动生成，看板里填模型密钥即可。

# 1. 运行安装包（可勾选「初始化示例任务」）
orcsy-setup-0.18.0.exe

# 2. 打开看板（浏览器自动打开），在「项目与设置」页：
#    填写 llm.api_key / base_url / model（OpenAI 兼容协议，覆盖
#    DeepSeek / GLM / Kimi / 通义 / Ollama / vLLM 等），再新建项目

# 3. 新建任务或往项目 tasks/ 放任务文件，点「立即扫描一轮」
# 配置文件位于 %APPDATA%\Orcsy\config.yaml（本地实体，不受 OneDrive 干扰）
GitHub Releases Gitee Releases

需要本机有 uv；首次运行自动准备 Python 3.11+ 环境。

# 1. 克隆并同步依赖
git clone https://github.com/easy-open-meta/Orcsy.git orcsy && cd orcsy
uv sync

# 2. 初始化运行目录（生成 config.yaml 与模板）
uv run orcsy init --dir run

# 3. 编辑 run/config.yaml：填 api_key/base_url/model，projects 指向你的项目；
#    在每个受管项目里放 AGENT.md 与 tasks/*.md（可从模板复制）

# 4. 校验配置与任务清单
uv run orcsy validate --config run/config.yaml

# 5. 启动 Web 看板（含定时调度，自动打开浏览器）
uv run orcsy web --config run/config.yaml

# 也可以纯 CLI 持续调度 / 试运行一轮（供外部 cron 或计划任务触发）
uv run orcsy run --config run/config.yaml
uv run orcsy run --config run/config.yaml --once

镜像基于 Python 3.12 slim，多阶段 uv 构建、按 uv.lock 可复现；应用以非 root 用户运行。

# 1. 构建并启动（数据落在 ./orcsy-data，受管仓库放 ./projects）
docker compose up -d --build

# 2. 打开看板 http://localhost:5116，在「项目与设置」页填写 llm.api_key，
#    项目路径指向容器内挂载点 /projects/<项目名>（需是 git 仓库）

# 外网部署务必设置看板登录密码（web.auth_password）

系统级服务：专用用户运行、开机自启、崩溃自动拉起。

# 上传/克隆源码后，在仓库根目录执行（需要 root；
# 自动装 uv、建用户、装服务并启动）
sudo bash deploy/linux/install.sh

# 打开看板 http://<服务器IP>:5116，填写 api_key 并新建项目
# （路径填 /srv/orcsy-projects/<项目名>）

systemctl status orcsy            # 运行状态
sudo systemctl restart orcsy      # 改配置后重启生效
journalctl -u orcsy -f            # 跟踪服务日志
